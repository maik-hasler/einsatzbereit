== Architecture Decisions

The following table lists the relevant architecture decisions. Each decision links to the corresponding ADR with full context, rationale, and considered alternatives.

.Architecture Decisions
[cols="1,4,8,3,3,3" options="header"]
|===
|No. |Context |Description |Status |Date |ADR

|1
|Monorepo
|Manage all components in a single repository.
|Accepted
|2026-03-23
|link:ADRs/1_monorepository.html[Monorepo]

|2
|arc42
|Use arc42 as the template for architecture documentation.
|Accepted
|2026-03-25
|link:ADRs/2_arc42.html[arc42]

|3
|Keycloak
|Use Keycloak as the Identity and Access Management solution.
|Accepted
|2026-03-25
|link:ADRs/3_keycloak.html[Keycloak]

|4
|Geocoding
|Geocode addresses at write time via Nominatim; spatial filtering by bounding box plus in-memory Haversine (no PostGIS).
|Accepted
|2026-05-13
|link:ADRs/4_geocoding_and_geo_search.html[Geocoding]

|5
|Map/geocoding proxying
|Proxy OpenStreetMap tile and Nominatim requests through the backend so visitor IP addresses are never sent to these third parties directly.
|Accepted
|2026-07-27
|link:ADRs/5_map_and_geocoding_request_proxying.html[Proxying]

|6
|Distributed tracing
|Add Grafana Tempo to the staging/production monitoring stack and point the backend's OTLP exporter at it; fix the log-level override that was silently suppressing HTTP request logs.
|Accepted
|2026-07-29
|link:ADRs/6_distributed_tracing_via_tempo.html[Tempo]

|7
|Shared monitoring stack ownership
|Move Grafana/Prometheus/Loki/Alertmanager/node-exporter/Alloy/Tempo to `mgmt-hetzner` as shared, label-driven host infra instead of living inside this repo.
|Accepted
|2026-08-21
|link:ADRs/7_shared_monitoring_stack_ownership.html[Shared monitoring]

|===

See <<section-solution-strategy>> for how the key decisions map to the quality goals.
