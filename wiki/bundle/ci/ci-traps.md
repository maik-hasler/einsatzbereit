Failure modes that a passing local build or a green single-PR run does not catch. Each has a known cause and a known fix.

# Non-ASCII dashes fail everywhere

CI rejects any Unicode dash (U+2013 en dash, U+2014 em dash) in **any** file, not only prose (`AGENTS.md:57`). LLM output emits them by default as an all-purpose sentence connector, so the failure recurs on nearly every doc or comment an agent writes. The fix is to restructure the sentence, not to reach for a dash and hope; when a connector is genuinely needed, use a plain ASCII hyphen (`-`). Treat this as a writing habit, not a find-and-replace at the end.

# Tabs are the default indent, spaces are the exception

The `.editorconfig` `[*]` rule makes **tab** indentation the default for the whole repo (`AGENTS.md:58`). Only `.md`, `.json`, `.yml`/`.yaml`, and `.py` are overridden to spaces. This is the reverse of the common assumption that spaces are the norm and tabs the special case, so shell scripts, `.adoc`, and `.puml` all take tabs. CI's `editorconfig` job enforces it. A space-indented continuation line on a wrapped JSX comment (the usual manual line-wrap alignment) failed this check in #702; the fix was collapsing the comment to one line rather than hand-indenting the continuation.

# EF scaffolding emits 4-space indentation and a BOM

`dotnet ef migrations add` writes its files with 4-space indentation and a UTF-8 BOM, both of which fail the `editorconfig` job (#702, #716). `dotnet format whitespace` is not a reliable cleanup here. It skips the `.Designer.cs` and `ModelSnapshot.cs` files, whose `<auto-generated />` header makes formatters ignore them by default (#702), and whitespace-only mode may not re-tab existing indentation at all (#716). The dependable fix is by hand: convert leading spaces to tabs at 4:1 and strip the BOM so the new migration matches every other one in the repo. In #716 this slipped past a first `dotnet format whitespace` pass and was only caught by `ef-migration-check` during self-review.

# IntegrationTests can hang for over an hour

The `IntegrationTests` step (Testcontainers) can sit "in progress" for 70+ minutes with no step transitions - a hang, not a slow run (#689). Re-running the job through the Actions API was not permitted for the session's token, so the accepted recovery is an empty commit, `chore: re-trigger CI`, to kick a fresh run. This bites hardest at the "CI green before release" gate, where a stuck run blocks the release with nothing actually wrong.

# Two green PRs can still break main

A PR's CI runs against its own base, so it never exercises another in-flight PR's change. Two PRs that each pass alone can break `main` once both land. #716 (the DDD refactor) replaced Organization's `Update(...)` and `new Address(...)` with `Rename`/`ChangeDescription`/`ChangeContactInfo`/`Relocate` and `Address.Create(...)`. #715, branched before that, extended `CreateOrganizationCommandHandler` while still calling the old API. Each merged green; the build broke only on `main`, because the merge was textually clean but semantically conflicting. #718 restored the build by porting the handler to the new factory methods. No per-PR check catches this class of break - watch for it whenever a refactor of a shared API overlaps with feature work that touches the same call sites.
